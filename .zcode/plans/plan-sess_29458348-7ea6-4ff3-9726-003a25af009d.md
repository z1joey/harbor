## 目标

多项目并行开发时，端口冲突从"启动失败才发现"变为"规划期/启动前就预警"，并支持一键腾出占用端口。策略：静态号段规划 + 跨项目静态预警 + 修复托管进程间冲突漏报。Harbor 不改写你的应用配置，端口号仍由你在项目内手动约定。

## 配置形态（新增 `[[port_claim]]`）

现有 `[[process]].port` 语义不变。新增项目级端口声明，覆盖"一个进程占多个端口"（如 compose 起 postgres+redis）及"非 Harbor 管理的基础设施端口"：

```toml
[[port_claim]]
port = 5432
note = "postgres"
process = "deps"   # 可选，指向已定义的进程名，仅用于展示
```

项目实际声明的端口 = 各进程 `port` ∪ 所有 `port_claim`。

## 实施内容

**1. 模型与解析** — `Project` 新增 `portClaims: [PortClaim]`（`PortClaim { port, note?, processName? }`）；`HarborConfigParser` 解析 `[[port_claim]]`（端口范围校验、项目内去重、`process` 若给出须指向已定义进程），模板 `templateText` 加注释示例；非法配置仍走现有 `configError` 展示。

**2. 冲突扫描重构（核心，可测试）** — 新建 `App/Services/PortPlanner.swift`，纯函数（不依赖 UI/单例），把冲突逻辑从 `AppState.conflicts` 中抽出：
- `runtimeConflicts`：每个项目声明端口若被占用则报冲突，区分两类——外部占用者（现状，未管理 PID）与 **其他 Harbor 管理项目的占用者（当前完全漏报，此次修复）**；同项目自身占用不算冲突。
- `staticOverlaps`：被 ≥2 个项目声明的端口（静态重叠，与是否运行无关）。
- `suggestFreePorts`：给定已声明端口全集 ∪ 当前监听端口，从基准值起推荐空闲端口。
- `AppState.conflicts` 改为调用 PortPlanner；`ProcessSupervisor` 暴露 `projectID(forPID:)`（内部已有 `key(forPID:)`）。菜单栏图标维持"运行时冲突"语义，静态重叠只在窗口内展示。

**3. 启动流程与一键腾端口** — 冲突确认框在"仍然启动/取消"外新增第三个动作"结束占用者并启动"：托管占用者走 `supervisor.stop`（优雅停止），外部占用者走现有 `ProcessKiller.terminateTree`（保留确认语义），完成后自动启动。`PendingConflict` 增加占用者类型字段。`ProjectConflictDialogs` 与 `MenuBarPopoverView` 里的两份内联对话框目前是重复代码，此次抽成共享组件一并维护。Start-all 流程同样支持。

**4. 端口总览视图** — 主窗口侧栏新增"端口总览"项（与 Listening Ports 并列），新视图 `App/Views/Ports/PortsOverviewView.swift`：按端口排序，每行显示端口号、声明它的项目（含 note/进程）、当前状态（空闲 / 被某项目某进程托管占用 PID / 被外部进程占用 / ⚠ 多项目重叠），提供"结束占用者""打开项目"操作；顶部汇总静态重叠警告。

**5. 添加/导入项目时的预警与建议** — `AddProjectSheet` 与 `ImportDraftEditor` 在配置解析后调用 PortPlanner：检测与现有项目的声明端口重叠并内联警告；提供建议空闲端口（模板生成的注释中也填入建议值）。修复现状"导入时完全不检测端口"。

**6. 文档与验收** — README 配置 schema（`[[port_claim]]`）与冲突规则更新；`docs/ACCEPTANCE.md` 增补对应验收项。

## 测试（沿用现有 XCTest 模式）

- `ConfigParserTests`：port_claim 解析/校验/去重/process 引用校验/模板往返。
- 新增 `PortPlannerTests`：托管-托管冲突、外部冲突、同项目不算、静态重叠、端口推荐。
- `ProcessSupervisorTests`：`projectID(forPID:)`。
- 全量构建 + 测试（本机需 `DEVELOPER_DIR=/Applications/Xcode.app`）。

## 明确不做（本期）

自动改写/重编你项目内的端口配置、动态 `PORT` 环境变量注入（可作为二期）、compose 文件解析、对 80/443 的特殊处理（作为普通声明即可）。
